# Может ли сеть зависнуть?

**Да.** Сеть достигает тупиковой маркировки за два шага: **t1, затем t4** (или t4, затем t1).

## Сеть

| Переход | Вход | Выход |
|---|---|---|
| t1 | p1 | p2 |
| t2 | p2, p4 | p3 |
| t3 | p3 | p1, p4 |
| t4 | p4 | p5 |
| t5 | p1, p5 | p6 |
| t6 | p6 | p4, p1 |

Начальная маркировка M0 = {p1=1, p4=1}.

## Контрпример (трасса в тупик)

```
{p1=1, p4=1}  --t1-->  {p2=1, p4=1}  --t4-->  {p2=1, p5=1}
```

В маркировке {p2=1, p5=1} ни один переход не разрешён:

- t1 требует p1 — пусто;
- t2 требует p2 **и** p4 — p4 пусто (фишка ушла в p5 через t4);
- t3 требует p3 — пусто;
- t4 требует p4 — пусто;
- t5 требует p1 **и** p5 — p1 пусто (фишка ушла в p2 через t1);
- t6 требует p6 — пусто.

Это классический «взаимный захват»: фишка из p1 ушла по ветке t1 (ей теперь нужен p4), а фишка из p4 одновременно ушла по ветке t4 (ей теперь нужен p1). Каждая ветка ждёт ресурс, который другая уже забрала.

## Полный граф достижимости

Сеть 1-безопасная (ни в одном месте больше одной фишки), всего 6 достижимых маркировок:

```
M0 {p1,p4} --t1--> M1 {p2,p4}
M0 {p1,p4} --t4--> M2 {p1,p5}
M1 {p2,p4} --t2--> M3 {p3}        --t3--> M0
M1 {p2,p4} --t4--> M4 {p2,p5}     (ТУПИК)
M2 {p1,p5} --t1--> M4 {p2,p5}     (ТУПИК)
M2 {p1,p5} --t5--> M5 {p6}        --t6--> M0
```

Инварианты мест (объясняют безопасность): p1+p2+p3+p6 = 1 и p3+p4+p5+p6 = 1.

Итог: из 6 маркировок ровно одна тупиковая — M4 = {p2=1, p5=1}, и она достижима из M0. «Хорошие» циклы (t1·t2·t3 и t4·t5·t6) существуют, но сеть не обязана по ним идти: при недетерминированном выборе достаточно один раз сработать t1 и t4 «вразнобой», и сеть встаёт навсегда.

## Как избежать зависания (если нужно)

Тупик исчезает, если сделать захват двух ресурсов атомарным, например заменить пару t1/t2 на один переход t12: p1, p4 → p3 (и симметрично t4/t5 на t45: p1, p4 → p6). Тогда обе ветки берут оба ресурса сразу и «полузахваченного» состояния не возникает.

## Артефакты

- `reach.py` — полный перебор графа достижимости (BFS), печатает все маркировки, дуги, тупики и трассу к ним.
- `reach-output.txt` — вывод скрипта.
