# Model check: `Promela - examples/CH17/simple1.pr` (процесс `simple`, переменная `x` во встроенном C)

## 1. Summary

**Исходная модель (`simple1.pr`) — не проверена.** Движок отклонил файл на входе:
`c_code` (строка 1) — встроенный C, вне принимаемого подмножества Promela; код на языке
хоста движок не исполняет по требованию NFR-004. Ни одно свойство не выполнялось:

- P1 (нет недопустимых конечных состояний / тупиков): `not-executed`, evidence `unknown`.
- P2 (`assert(c_expr { x==4 })`, `assert(c_expr { x==6 })` не нарушаются): `not-executed`, evidence `unknown`.

Статусы `not-executed` присвоены мной, а не движком: движок не создал ни одной записи о
свойстве (код выхода 2, документ-отказ вместо отчёта).

**Перепись внутри подмножества (`simple1-rewrite.pml`, файл написан мной, исходник не
менялся) — проверена полностью.** Встроенный C заменён на присваивания и гарды Promela с
тем же арифметическим эффектом на `x`. На переписанной модели, при допущениях A1–A2
из §2, исчерпывающий поиск (8 состояний, 7 переходов, глубина 4):

- P1 (тупики): `verified`, evidence `exhaustive`.
- P2 (оба `assert`): `verified`, evidence `exhaustive`.
- P3 (sanity: состояние `x == 4` достижимо): `verified`, evidence `exhaustive`, свидетель `x = 2, x = x + 2`.
- P4 (sanity: состояние `x == 6` достижимо): `verified`, evidence `exhaustive`, свидетель `x = 2, x = x * 3`.

Это результат о **переписанной** модели. Переносить его на исходный файл с `c_code`
можно только при условии, что допущения A1–A2 верны — подтвердить их должен пользователь
(вопросы в §10).

## 2. Scope and assumptions

- **Граница системы.** Один процесс `simple` (`active proctype`) и одна переменная `x`.
  Окружения нет: ни каналов, ни входов, ни других процессов. Ничего не исключено.
- **Семантика переходов.** Чередование (при одном процессе — тривиально); атомарный шаг —
  один оператор Promela. В SPIN каждый блок `c_code { … }` исполняется как один
  атомарный шаг; в переписи каждому блоку соответствует ровно один оператор, так что
  гранулярность совпадает.
- **Справедливость.** `none`. Свойства только safety (тупик, `assert`, достижимость);
  liveness-свойств нет, поэтому вопрос о справедливости не стоит.
- **Границы и ёмкости.** `x` — `int`; в модели принимает значения 0, 2, 4, 6, переполнения
  нет (движок остановился бы с `invalid-model`). 1 процесс, 0 каналов.
- **Отношение к реализации.** Учебный пример из корпуса книги по Spin (глава 17,
  встроенный C). Вручную написанная модель; утверждений о какой-либо реализации нет.
- **Допущения, принятые по умолчанию (пользователь недоступен, не подтверждены):**
  - **A1.** Блоки `c_code` не делают ничего, кроме показанного изменения `x`
    (`x = 2`, `x = x+2`, `x = x*3`); `c_expr` — чистые сравнения без побочных эффектов.
  - **A2.** Каждый блок `c_code` — один атомарный шаг (стандартная семантика SPIN).
  - **A3.** Начальное значение `x` = 0 (C-глобал); оно не влияет на результат, так как
    первый шаг присваивает `x = 2`.
  - **A4.** Цель проверки — исчерпывающий результат (для учебного примера); хранить
    модель и трассы в рабочей директории можно (секретов нет).

## 3. Model

**Исходный файл** (`Promela - examples/CH17/simple1.pr`, sha256
`d7a34d64…2b70`, не изменялся):

```
c_code { int x; }                              /* строка 1 — отклонено парсером */

active proctype simple()
{
   c_code { x = 2; };
   if
   :: c_code { x = x+2; }; assert(c_expr { x==4 })
   :: c_code { x = x*3; }; assert(c_expr { x==6 })
   fi
}
```

**Перепись** (`mc-session-2026-09-25/simple1-rewrite.pml`, sha256 `4831423a…1509`):

```
int x;

active proctype simple()
{
   x = 2;
   if
   :: x = x+2; assert(x == 4)
   :: x = x*3; assert(x == 6)
   fi
}
```

- Переменные состояния: `x : int` (глобальная); размер вектора состояния 6 байт.
- Процесс `simple:0`: 6 локаций (в том числе `end` и `-dead-`), 6 рёбер:
  `x = 2` → выбор ветви → `x = x + 2; assert(x == 4)` либо `x = x * 3; assert(x == 6)`
  → `-end-`.
- Начальное состояние: `x = 0`, `simple` в локации 0.
- Таблица соответствия (исходник → модель):

  | Исходник | Перепись | Замечание |
  |---|---|---|
  | `c_code { int x; }` | `int x;` | в SPIN C-переменная **не** входит в вектор состояния (без `c_track`/`c_state`); в переписи входит |
  | `c_code { x = 2; }` | `x = 2` | один атомарный шаг в обоих случаях |
  | `c_code { x = x+2; }` | `x = x+2` | — |
  | `c_code { x = x*3; }` | `x = x*3` | — |
  | `assert(c_expr { x==4 })` | `assert(x == 4)` | — |
  | `assert(c_expr { x==6 })` | `assert(x == 6)` | — |

- Предупреждения парсера: для переписи — нет (stderr пуст; `warnings` в отчёте
  отсутствуют). Для исходника — не предупреждение, а отказ (§6).

## 4. Properties

Классификация выполнена вручную по `references/properties-ltl-ctl.md` — CLI-эквивалента

sanity-свойства (шаг 4 рабочего процесса): без них `verified` для P2 мог бы быть
вакуумным, если бы какая-то ветвь была недостижима.

## 5. Method and backend

- Движок: `mcd` версии `0.1.0-g0` (встроенный explicit-state движок; схемы `mcd-ir/1`,
  `mcd-report/1`), через CLI `/tmp/mcd` — MCP-сервер в сессии не зарегистрирован, а в
  этой сборке сервер и так не подключает Promela-фронтенд, так что CLI — единственный
  путь для Promela.
- Поиск: DFS (основной прогон) и контрольный BFS; справедливость `none`; редукции: нет
  (поиск без POR, симметрии и абстракций).
- Почему метод подходит: модель конечная (один `int` с четырьмя значениями, один
  процесс), untimed, недетерминизм — только выбор ветви `if`; полный перебор
  достижимого графа тривиален по размеру. Для исходного файла метод неприменим не
  из-за класса модели, а из-за входного конструкта: `c_code` требует исполнения
  C-кода хоста, чего движок не делает намеренно.

## 9. Limitations

1. **Исходный файл не проверен.** `c_code` / `c_expr` — за границей подмножества движка
   по проекту (NFR-004: код хоста не исполняется). Это граница инструмента, а не дефект
   модели: `simple1.pr` — корректная модель для SPIN, которую этот движок не читает.
   Поэтому статус `not-executed`, а не `invalid-model`.
2. **Результат относится к переписи.** Соответствие переписи исходнику держится на
   допущениях A1–A2 (C-код меняет только `x`; каждый блок — один шаг). Для этого
   конкретного файла они выглядят очевидными (три присваивания, два сравнения), но
   пользователь их не подтверждал. При любом другом C-коде (вызовы функций, указатели,
   статические переменные, ввод-вывод) такая перепись невозможна без ручного анализа.
3. **Различие в векторе состояния.** В SPIN переменная из `c_code { int x; }` не
   входит в вектор состояния (нужны `c_track`/`c_state`), в переписи `x` — обычная
   Promela-переменная и входит. На результат свойств здесь это не влияет (один процесс,
   без циклов), но число состояний у SPIN на исходнике и у движка на переписи (8)
   сравнивать нельзя.
4. Поиск без редукций (POR отсутствует в этой сборке) — при 8 состояниях несущественно.
5. `mc_simulate` и `mc_lint_property` не запускались (нет CLI-аналогов); классификация
   свойств — ручная.
6. О реализации ничего не утверждается: модель учебная, аргумента соответствия нет.
