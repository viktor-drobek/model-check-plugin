# Проверка модели `Promela - examples/CH17/simple1.pr`

## Модель

```promela
c_code { int x; }

active proctype simple()
{
   c_code { x = 2; };
   if
   :: c_code { x = x+2; }; assert(c_expr { x==4 })
   :: c_code { x = x*3; }; assert(c_expr { x==6 })
   fi
}
```

Один процесс, одна C-переменная `x`, два недетерминированных варианта.
Арифметически оба `assert` верны: `2+2 = 4`, `2*3 = 6`. Тем не менее
верификация находит нарушение — и это не случайность, а дефект самой модели.

## Вердикт

**Модель в текущем виде некорректна для верификации: `pan` сообщает
`assertion violated (x==6)`, при этом контрпример невоспроизводим.**
Причина — переменная `x` объявлена внутри `c_code { int x; }` без `c_track`,
поэтому она не входит в вектор состояний и не восстанавливается при откате
поиска в глубину. Исправление (`c_track "&x" "sizeof(int)"`) даёт полный
обход без ошибок.

## Чем проверял и почему

| Инструмент | Результат |
|---|---|
| Движок репозитория `mcd` (`model-check-plugin/engine`) | **Отказ**: `outside-subset`, `status: not-executed`, «`c_code` (embedded C is outside the subset)», строка 1. Парсер движка явно перечисляет `c_code`/`c_decl`/`c_state`/`c_track`/`c_expr` как конструкции вне поддерживаемого подмножества (`frontend/promela/parser.go`). |
| Spin 6.5.2 + gcc (`spin -a`, `gcc`, `./pan`) | Полная проверка выполнена, см. ниже. |

То есть для модели со встроенным C единственный работающий путь здесь — сам
Spin; движок репозитория честно сообщает границу своей области, а не даёт
неверный ответ. Логи движка: `engine-parse.txt`, `engine-check.txt`.

## Результат Spin на исходной модели (`spin-original/`)

```
pan:1: assertion violated ( x==6 ) (at depth 2)
pan: wrote simple1.pr.trail
State-vector 12 byte, depth reached 4, errors: 1
        6 states, stored
```

Трасса (`spin -t -p`, файл `trail-replay.log`):

```
1: simple1.pr:5  [{ x = 2; }]
2: simple1.pr:8  [{ x = x*3; }]
3: simple1.pr:8  [assert( x==6 )]
```

Взятая сама по себе, эта трасса **не** нарушает утверждение: `2*3 = 6`.
Проверка воспроизводимости через `./pan -r` (единственный способ реально
выполнить C-фрагменты при воспроизведении, файл `pan-r-replay.log`):

```
1: [ x = 2; ]
2: [ x = x*3; ]
3: [assert( x==6 )]
spin: trail ends after 3 steps
   -end-
global vars:          <- пусто: x не в векторе состояний
```

Нарушения нет. Контрпример невоспроизводим — классический признак
неотслеживаемого C-состояния.

### Механизм ошибки

`pan` выполняет DFS. `x` — обычная C-глобальная переменная (в `pan.c` она
просто `int x;`), её нет в векторе состояний (12 байт — это только служебные
поля процесса), поэтому при откате её значение **не** возвращается назад:

1. `x = 2`; первая ветка: `x = x+2` → `x = 4`; `assert(x==4)` проходит; конец.
2. Откат ко второму варианту `if`. В векторе состояний ничего не менялось,
   но `x` по-прежнему `4`.
3. Вторая ветка: `x = x*3` → `x = 12`; `assert(x==6)` **нарушен**.

Результат зависит от порядка обхода: если бы DFS пошёл сначала по второй
ветке, нарушилось бы `x==4` (`6+2 = 8`). Сообщение об ошибке, таким образом,
описывает не поведение модели, а артефакт способа её хранения.

Судя по имени каталога (`CH17` — глава 17 «Embedded C Code» книги Хольцмана
о Spin), пример, по-видимому, иллюстрирует именно этот эффект; в текстах книг
из `books-md/` этого примера нет, так что это моё предположение, а не цитата.

## Исправленная копия и её проверка (`spin-fixed/`)

Исходный файл не менял; рядом положена копия `simple1_tracked.pr` с одной
добавленной строкой:

```promela
c_code { int x; }
c_track "&x" "sizeof(int)"
```

`./pan` на ней:

```
State-vector 20 byte, depth reached 4, errors: 0
        8 states, stored
unreached in proctype simple
	(0 of 8 states)
```

Вектор состояний вырос с 12 до 20 байт (в него вошла `x`), оба варианта `if`
обошлись, оба `assert` выполнены, все состояния достижимы, файл `.trail` не
создан. Ошибка ушла.

Альтернативы с тем же эффектом:

- `c_state "int x" "Global"` и обращение к `now.x` в C-фрагментах;
- для *этой* модели встроенный C вообще не нужен — обычная `int x` в Promela
  даёт то же поведение и полностью поддерживается любым верификатором,
  включая движок репозитория.

## Артефакты (все в этом каталоге)

| Файл | Содержимое |
|---|---|
| `simple1.pr` | копия проверяемой модели |
| `engine-parse.txt`, `engine-check.txt` | ответ движка `mcd` (`outside-subset`) |
| `spin-original/verification.log` | `spin -a`, `gcc`, `./pan` на исходной модели (1 ошибка) |
| `spin-original/simple1.pr.trail` | трасса контрпримера |
| `spin-original/trail-replay.log` | `spin -t -p -g` (печать трассы, C не выполняется) |
| `spin-original/pan-r-replay.log` | `./pan -r` — воспроизведение с выполнением C, нарушения нет |
| `spin-fixed/simple1_tracked.pr` | исправленная копия с `c_track` |
| `spin-fixed/verification.log` | полный обход исправленной копии, 0 ошибок |

Сгенерированные `pan.c`/`pan.*` и бинарники `pan` удалены, чтобы не
захламлять каталог; все команды записаны в логах и воспроизводимы.

## Допущения

- Использован системный Spin 6.5.2 и gcc; предупреждения gcc о `sprintf` в
  `pan.c` — известная особенность генерируемого кода Spin, к результату не
  относятся.
- Проверялись только safety-свойства (assert, invalid end states) — других
  свойств модель не задаёт; `never`/LTL-утверждений в ней нет.
