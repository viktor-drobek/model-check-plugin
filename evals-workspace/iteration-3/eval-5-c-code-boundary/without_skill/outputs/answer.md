# Проверка модели `Promela - examples/CH17/simple1.pr`

**Файл:** `${REPO_ROOT}/Promela - examples/CH17/simple1.pr`
**Инструменты:** Spin 6.5.2 (6 December 2019), gcc 15.2.0, Linux.
**Дата прогона:** 2026‑09‑25.

## Исходная модель

```promela
c_code { int x; }

active proctype simple()
{
   c_code { x = 2; };
   if
   :: c_code { x = x+2; }; assert(c_expr { x==4 })
   :: c_code { x = x*3; }; assert(c_expr { x==6 })
   fi
}
```

## Краткий вывод

**Модель синтаксически корректна, но верификационно некорректна.** Полный перебор
даёт «нарушение assert `x==6`», которого в действительности нет: это **ложное
срабатывание**, вызванное тем, что переменная `x` объявлена внутри `c_code` и
потому **не входит в вектор состояния** Spin. При backtracking'е поиска в глубину
её значение не восстанавливается.

Причина ровно одна и она устраняется одной строкой — `c_track "&x" "sizeof(int)"`
(именно это и есть отличие соседнего файла `simple2.pr`, см. ниже).

Статус модели: **FAIL по формальному прогону, но контрпример невоспроизводим ⇒
результат прогона не является доказательством ошибки в модели; ошибка — в самой
модели как объекте верификации (незатреканное C‑состояние).**

---

## 1. Синтаксис и трансляция

```
$ spin -a simple1.pr
```

Ошибок и предупреждений нет, `pan.[chmbpt]` сгенерированы.
Компиляция `gcc -O2 -DSAFETY -o pan pan.c` — без диагностики.
(Лог: `work/01-spin-a.txt`, `work/02-compile.txt`.)

## 2. Полный перебор (assertions + invalid end states)

```
$ ./pan -m10000
pan:1: assertion violated ( x==6 ) (at depth 2)
pan: wrote simple1.pr.trail

State-vector 12 byte, depth reached 4, errors: 1
        6 states, stored
        0 states, matched
```

(Лог: `work/03-pan-run.txt`.)

Ключевая цифра — **State-vector 12 byte**. В нём лежат только служебные поля и
управляющее состояние процесса `simple`; четырёх байт под `x` там нет. Поиск
Spin'а не знает о существовании `x`.

## 3. Контрпример невоспроизводим

Проигрывание трейла средствами самого pan (единственный корректный способ для
моделей с `c_code`):

```
$ ./pan -r
  1: proc 0 (simple) simple1.pr:5 (state 1) [ x = 2; ]
  2: proc 0 (simple) simple1.pr:7 (state 6) [ x = x*3; ]
  3: proc 0 (simple) simple1.pr:8 (state 5) [assert( x==6 )]
spin: trail ends after 3 steps
```

Нарушения **нет**: на этом пути `x = 2`, затем `x = 2*3 = 6`, и `x==6` истинно.
То есть pan сообщил об ошибке, которую его же реплей не воспроизводит. Это
классический признак «протекания» состояния между ветвями поиска.

Отдельно: `spin -t -p simple1.pr` для такой модели пользоваться **нельзя**, Spin
сам это говорит:

> `this model contains embedded c code statements ... they are just printed, which will likely lead to inaccurate variable values. for an accurate replay use: ./pan -r`

(Логи: `work/04-trail-replay.txt`, `work/05-pan-replay.txt`.)

## 4. Прямое доказательство причины

Инструментированная копия с `printf` внутри тех же `c_code`‑блоков
(`work3/probe1.pr`) при том же полном переборе печатает:

```
[probe] set x=2
[probe] branch A: x=4
[probe] branch B: x=12      <-- ожидалось 6
pan:1: assertion violated ( x==6 ) (at depth 2)
```

Механика: DFS идёт в первую ветвь `if`, выполняет `x = x+2` → `x = 4`,
`assert(x==4)` проходит; затем **откатывается** к точке ветвления. Откат
восстанавливает только вектор состояния Spin, а `x` живёт в C‑памяти вне этого
вектора, поэтому остаётся равным 4. Вторая ветвь считает `x = 4*3 = 12`, и
`assert(x==6)` падает. (Лог: `work3/07-probe-run.txt`.)

## 5. Исправление и контрольный прогон

Рядом в каталоге лежит `simple2.pr`. `diff` показывает единственное отличие:

```
1a2
> c_track "&x" "sizeof(int)"
```

Прогон `simple2.pr`:

```
State-vector 20 byte, depth reached 4, errors: 0
        8 states, stored
unreached in proctype simple
	(0 of 8 states)
```

**0 ошибок**, вектор состояния вырос с 12 до 20 байт (в него вошёл `x` +
выравнивание), число состояний 6 → 8 (две ветви перестали склеиваться).
Покрытие полное — недостижимых состояний нет. (Лог: `work2/06-simple2-run.txt`.)

Таким образом: обе assert'ы в исходной модели **в действительности верны**;
`simple1.pr` — это намеренно сломанный образец, показывающий цену отсутствия
`c_track`, а `simple2.pr` — его исправленная версия.

## 6. Вторая, более опасная сторона той же границы (ложные отрицания)

Ложное срабатывание хотя бы заметно. Обратный эффект — **молчаливо пропущенная
ошибка**. Минимальный пример (`work4/fn_notrack.pr`):

```promela
c_code { int x = 0; }
active proctype p()
{
   do
   :: c_code { x++; }
   :: break
   od;
   assert(c_expr { x != 5 })
}
```

| вариант | State-vector | states stored | результат |
|---|---|---|---|
| без `c_track` | 12 byte | 3 | **errors: 0** (ошибка пропущена) |
| с `c_track "&x" "sizeof(int)"` | 20 byte | 29 985 | `assertion violated (x != 5)` at depth 5 |

Без `c_track` управляющее состояние после каждой итерации цикла одинаково, Spin
сопоставляет его с уже посещённым и обрывает перебор на 3 состояниях — значение
`x = 5` никогда не достигается. Верификатор при этом **рапортует успех**.
(Лог: `work4/08-false-negative.txt`.)

## 7. Про `c_track ... "UnMatched"`

Проверено отдельно (`work5/`):

| модель | `c_track` | результат |
|---|---|---|
| `simple1` | `"Matched"` (по умолчанию) | 0 ошибок, 6 состояний — **починено** |
| `simple1` | `"UnMatched"` | 0 ошибок, 6 состояний — **починено** |
| цикл из §6 | `"Matched"` | ошибка найдена |
| цикл из §6 | `"UnMatched"` | 3 состояния, **ошибка по‑прежнему пропущена** |

Вывод: `UnMatched` восстанавливает данные при backtracking'е (лечит §4), но не
включает их в сопоставление состояний (не лечит §6). Для `simple1.pr` хватило бы
и `UnMatched`, но по умолчанию правильный выбор — `Matched`.

## Итоговые рекомендации

1. **Использовать `simple2.pr`, а не `simple1.pr`**, если нужна валидная проверка
   этой логики. В `simple1.pr` ничего не менять — это учебный контрпример.
2. Правило для любых моделей с `c_code`: **любая C‑переменная, влияющая на
   поведение модели, должна быть объявлена через `c_state` либо объявлена в
   `c_code` и обязательно покрыта `c_track`.** Альтернатива для `simple1.pr` —
   `c_state "int x" "Global"` с обращением `now.x` (как в `example1` в том же
   каталоге).
3. Трейлы моделей с `c_code` проигрывать **только** через `./pan -r`; `spin -t`
   печатает C‑фрагменты, не выполняя их, и врёт про значения.
4. Реплей, который не воспроизводит сообщённую ошибку, — это не «флака», а
   надёжный индикатор незатреканного внешнего состояния. Проверять в первую
   очередь размер `State-vector`.
5. Проверялись только встроенные safety‑свойства (assert + invalid end states).
   LTL‑свойств в модели нет; цикловых проверок (`-DSAFETY` снят) не требуется —
   `simple()` ацикличен и завершается.

## Явно помеченные допущения

- **Допущение 1.** «Проверь модель» истолковано как: трансляция + компиляция +
  полный перебор safety (assertion violations и invalid end states) + разбор
  границы Promela/C. Пользователь недоступен, свойств в стиле LTL/never claim не
  задавал, поэтому liveness/acceptance‑циклы не проверялись.
- **Допущение 2.** Путь `Promela - examples/CH17/simple1.pr` разрешён
  относительно корня репозитория.
- **Допущение 3.** Исходный файл модели считается неизменяемым (это образец из
  книги). Все прогоны выполнены на копиях внутри `outputs/`; оригинал не
  редактировался. Исправление показано сравнением с уже существующим
  `simple2.pr`, а не патчем `simple1.pr`.
- **Допущение 4.** `simple1.pr`/`simple2.pr` опознаны как парный образец из
  главы 17 («Using Embedded C Code») книги Холцманна; это опознание влияет
  только на интерпретацию («намеренно сломан»), но не на результаты прогонов —
  они получены независимо.
