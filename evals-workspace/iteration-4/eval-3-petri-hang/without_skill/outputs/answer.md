# Может ли сеть зависнуть? — Да

**Короткий ответ: да, сеть может зависнуть (deadlock достижим), причём за два шага.**

Тупиковая маркировка — **p2 = 1, p5 = 1** (все остальные места пусты). В ней не разрешён ни один переход.

## Контрпример (кратчайшая последовательность срабатываний)

```
M0 = {p1=1, p4=1}
  --t1-->  {p2=1, p4=1}        (t1: p1 → p2, фишка ушла из p1)
  --t4-->  {p2=1, p5=1}        (t4: p4 → p5, фишка ушла из p4)
           ^^^^^^^^^^^^^^  тупик: ни один переход не разрешён
```

Проверка тупиковости `{p2=1, p5=1}` по всем шести переходам:

| переход | что требует на входе | почему не разрешён |
|---|---|---|
| t1 | p1 | p1 = 0 |
| t2 | p2, p4 | p2 = 1, но **p4 = 0** |
| t3 | p3 | p3 = 0 |
| t4 | p4 | p4 = 0 |
| t5 | p1, p5 | p5 = 1, но **p1 = 0** |
| t6 | p6 | p6 = 0 |

## Почему так получается (структурная причина)

У сети есть два P-инварианта (проверены на всём множестве достижимых маркировок):

* `p1 + p2 + p3 + p6 = 1` — «фишка A» ходит по кольцу p1 → p2 → p3 → p6 → p1;
* `p3 + p4 + p5 + p6 = 1` — «фишка B» ходит по кольцу p4 → p5 → p6 → p3 → p4.

Отсюда сразу следует, что сеть **безопасна (1-ограничена)**: в каждом месте не больше одной фишки, всего достижимо ровно 6 маркировок.

Два синхронизирующих перехода требуют обе фишки одновременно:

* **t2** нужен A в p2 **и** B в p4;
* **t5** нужен A в p1 **и** B в p5.

Каждая фишка может сдвинуться на один шаг самостоятельно: A через t1 (p1 → p2), B через t4 (p4 → p5). Если из начального состояния сдвинуть **обе** (A в p2 и B в p5), то для t2 фишка B уже «проскочила» p4, а для t5 фишка A уже «проскочила» p1 — встретиться им больше негде. Это классический deadlock вида «оба захватили не тот ресурс» (несогласованный порядок захвата).

## Полный граф достижимости (6 маркировок, 8 дуг)

| маркировка | разрешённые переходы |
|---|---|
| {p1=1, p4=1} ← начальная | t1, t4 |
| {p2=1, p4=1} | t2, t4 |
| {p1=1, p5=1} | t1, t5 |
| {p3=1} | t3 |
| {p6=1} | t6 |
| **{p2=1, p5=1}** | **нет — ТУПИК** |

Полный перебор пространства состояний подтверждает: тупиковая маркировка ровно одна, и она достижима.

## Важное уточнение: зависание не обязательно, но и не избегаемо

* Зависание **не неизбежно**: существует бесконечный корректный цикл, например
  `{p1,p4} --t4--> {p1,p5} --t5--> {p6} --t6--> {p1,p4} --t4--> ...`
  и второй цикл `{p1,p4} --t1--> {p2,p4} --t2--> {p3} --t3--> {p1,p4}`.
  То есть при «удачном» расписании сеть работает вечно.
* Но зависание **не может быть исключено выбором расписания**: проверка показывает, что из **каждой** из шести достижимых маркировок тупик всё ещё достижим (в терминах CTL: `AG EF deadlock` истинно). Никакая справедливость (fairness) здесь не помогает — тупик достигается не «нечестным» бесконечным откладыванием, а конечной последовательностью из двух шагов.
* Следовательно, сеть **не живая (not live)**: ни один переход не является живым, поскольку после попадания в `{p2, p5}` не сработает уже ничто.

## Как починить (если цель — независающая сеть)

Проблема в том, что t1 и t4 могут сработать независимо и «развести» фишки. Достаточно убрать эту независимость, например:

* добавить место-семафор `sync` с одной фишкой, которое требуется и отдаётся переходами t1 и t4, так чтобы после t1 стал невозможен t4 до срабатывания t2 (и симметрично);
* или объединить t1 и t4 в один переход, если по смыслу модели шаги должны быть согласованы;
* или добавить дугу-«часового», делающую t4 разрешённым только при p1 = 0 (ингибиторная дуга) — но это уже расширение классических сетей Петри.

Конкретный выбор зависит от того, что моделируется; исходная постановка этого не задаёт.

## Артефакты

Все файлы лежат рядом с этим ответом:

* `petri_reachability.py` — скрипт исчерпывающего перебора пространства состояний (обход в ширину, восстановление кратчайшей трассы до тупика, проверка P-инвариантов, проверка достижимости тупика из каждой маркировки);
* `reachability-report.txt` — полный вывод скрипта;

### Явно помеченные допущения

1. **Семантика сети — классические сети Петри**: дуги кратности 1, места без ёмкостных ограничений, ингибиторных дуг нет, переходы срабатывают по одному (интерливинг). Кратности дуг в постановке не указаны, поэтому приняты равными 1.
2. **«Зависнуть» = deadlock**, то есть достижима маркировка, в которой не разрешён ни один переход. Если под «зависнуть» имелось в виду «зациклиться без прогресса» (livelock/голодание), ответ тоже положительный в более слабом смысле: цикл `{p1,p4} → {p1,p5} → {p6} → {p1,p4}` может выполняться вечно, и тогда переходы t2 и t3 не срабатывают никогда.
3. Стартовая маркировка взята ровно как задано: `p1 = 1, p4 = 1`, остальные места пусты.
