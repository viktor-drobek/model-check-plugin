# Model check: `Promela - examples/CH17/simple1.pr`

## 1. Summary

Короткий ответ: **эту модель движок не проверял — и не может проверить.** Она
написана на встроенном C (`c_code`, `c_expr`), а это конструкция вне подмножества
Promela, которое читает движок. Парсер отверг файл на первой строке, отчёта нет,
ни одно свойство не исполнялось.

Оригинальный файл `Promela - examples/CH17/simple1.pr`:

- **P1** (`assert(c_expr { x==4 })` в первой ветви `if`): `not-executed`, evidence `unknown`.
- **P2** (`assert(c_expr { x==6 })` во второй ветви `if`): `not-executed`, evidence `unknown`.
- **P3** (нет тупика / невалидного конечного состояния): `not-executed`, evidence `unknown`.

Сводный статус прогона по приоритету агрегации — `not-executed`. Статус здесь
назначен мной, а не движком: движок вернул отказ во входе (exit code 2) и не создал
ни одной записи о свойстве.

Отдельно, **как предложенная переделка, а не как результат про исходный файл**, я
переписал модель внутри подмножества (C-эффекты — обычными присваиваниями Promela)
и проверил её. На переписанной модели `simple1-rewrite.pml` (8 состояний, поиск
завершён):

- **R-P1** `assert` (обе проверки сразу): `verified`, evidence `exhaustive`.
- **R-P2** `deadlock`: `verified`, evidence `exhaustive`.
- **R-P3** достижимость `x == 4`: `verified` (достижимо), evidence `exhaustive`, свидетель из 2 шагов.
- **R-P4** достижимость `x == 6`: `verified` (достижимо), evidence `exhaustive`, свидетель из 2 шагов.
- **R-P5** инвариант `x <= 6`: `verified`, evidence `exhaustive`.

Эти пять результатов — про `simple1-rewrite.pml`, не про `simple1.pr`. Почему
перенос не автоматический, сказано в §9.

## 2. Scope and assumptions

- **Граница системы.** Один процесс `active proctype simple()`. Окружения нет,
  каналов нет, второго процесса нет, чередования нет. Ничего не исключено намеренно.
- **Семантика переходов.** Interleaving (вырожденное: процесс один). Атомарный шаг —
  один оператор Promela; в SPIN каждый блок `c_code { … }` — один неделимый шаг.
- **Справедливость (fairness).** `none`. Все три свойства — безопасность; настройка
  справедливости на них не влияет, поэтому допущения о справедливости в результате нет.
- **Границы и ёмкости.** В оригинале `x` — это C-шная `int` (домен задаёт компилятор
  хоста, а не модель). В переделке `x` — Promela `int`. Значения в прогоне: 0 → 2 → 4 или 6.
- **Отношение к реализации.** Это учебная модель из корпуса (гл. 17 книги о SPIN,
  «Using Embedded C Code»); реализации, к которой что-то переносилось бы, нет.

**Явно помеченные допущения.** Пользователь для вопросов недоступен, поэтому вместо
обязательных вопросов рабочего процесса (§2 `references/workflow.md`) зафиксированы
допущения; полностью — в `intake-card.yaml`, здесь главные:

- **A1.** «Проверь эту модель» прочитано как: проверить свойства, которые модель
  заявляет сама (два `assert`), плюс отсутствие тупика. Новых требований я не придумывал.
- **A2.** Цель — исчерпывающий результат, а не только поиск одного сценария отказа.
- **A3** (про семантику оригинала, движком **не** проверено). В `simple1.pr` нет
  `c_track`, поэтому `x` живёт в памяти хоста и не входит в вектор состояния Promela.
  Соседний файл корпуса `CH17/simple2.pr` отличается от него ровно одной строкой —
  `c_track "&x" "sizeof(int)"`, — и именно в этом противопоставлении состоит смысл
  пары файлов. Проверить это утверждение данный движок не может: он host-код не
  исполняет вовсе. Держите его как замечание о SPIN, а не как результат.
- **A5.** Бюджет — умолчания CLI (модель крошечная).
- **A6.** Артефакты сложены в каталог `outputs/` этого прогона; файлы корпуса не
  копировались и не изменялись.

## 3. Model

Текст `Promela - examples/CH17/simple1.pr` целиком (10 строк):

```promela
c_code { int x; }

active proctype simple()
{
   c_code { x = 2; };
   if
   :: c_code { x = x+2; }; assert(c_expr { x==4 })
   :: c_code { x = x*3; }; assert(c_expr { x==6 })
   fi
}
```

- **Переменные состояния.** Ни одной переменной Promela. Единственная переменная `x`
  объявлена внутри `c_code` и принадлежит хосту (см. A3).
- **Процессы.** Один: `simple`, статический (`active`).
- **Переходы.** Инициализация `x = 2`; недетерминированный выбор одной из двух ветвей
  `if`; в первой — `x = x+2` и проверка `x==4`, во второй — `x = x*3` и проверка `x==6`;
  затем завершение.
- **Начальное состояние.** Процесс в начале тела; значение `x` до первого `c_code`
  моделью не задано.
- **Классификация (FR-003).** Конечность: конечная (домены ограничены, процесс один,
  каналов нет). Семантический класс: untimed — ни часов, ни вероятностей. Форма:
  асинхронная сеть процессов из одного процесса → маршрут «подмножество Promela».
  Ни один из выходов узлов 3 и 4 дерева решений не сработал; прогон остановился
  на шаге 3 (модель → IR), на границе подмножества.
- **Предупреждения парсера.** Их нет — парсер до предупреждений не дошёл, он отверг
  вход на первой строке.

**Таблица соответствия имён** (оригинал → переписанная модель, §10):

| В `simple1.pr` | В `simple1-rewrite.pml` |
|---|---|
| `c_code { int x; }` (строка 1) | `int x;` — глобальная переменная Promela |
| `c_code { x = 2; }` (строка 5) | `x = 2` |
| `c_code { x = x+2; }` (строка 7) | `x = x + 2` |
| `c_expr { x==4 }` (строка 7) | выражение Promela `x == 4` |
| `c_code { x = x*3; }` (строка 8) | `x = x * 3` |
| `c_expr { x==6 }` (строка 8) | выражение Promela `x == 6` |

## 7. Result

### 7.1. Исходный файл `Promela - examples/CH17/simple1.pr`

| ID | Status | Evidence | Counters | Примечание |
|---|---|---|---|---|
| P1 | `not-executed` | `unknown` | — | Конструкция `c_code` в строке 1 вне подмножества движка. Причина дословно: `construct outside subset: c_code (embedded C is outside the subset) (simple1.pr, line 1)`. Статус назначен мной: движок записи о свойстве не создал |
| P2 | `not-executed` | `unknown` | — | то же |
| P3 | `not-executed` | `unknown` | — | то же |

Сводно по приоритету агрегации (`invalid-model` > `not-executed` > `violated` >
`inconclusive` > `unknown` > `verified`): **`not-executed`**.

Важно, какая именно это граница. `not-executed` здесь — граница *подмножества
входного языка*, а не дефект модели: `simple1.pr` — вполне законная модель SPIN,
которую этот движок не читает. Поэтому статус — `not-executed`, а не
`invalid-model`. И это не временная нехватка функции, которую снимет следующая
сборка: отказ от `c_code`/`c_expr`/`c_decl` — сознательное ограничение (NFR-004,
«никакого host-кода»), движок не исполняет код модели как код хоста.

### 7.2. Переписанная модель `simple1-rewrite.pml` (другая модель, см. §9)

| ID | Status | Evidence | Counters | Примечание |
|---|---|---|---|---|
| R-P1 `assert` | `verified` | `exhaustive` | 8 состояний, 7 переходов, глубина 4 | Контрпримера ни для `x == 4`, ни для `x == 6` в исчерпывающем поиске не найдено; поиск завершён (`complete: true`) |
| R-P2 `deadlock` | `verified` | `exhaustive` | те же | Невалидных конечных состояний нет: процесс завершается штатно |
| R-P3 `reach_x4` | `verified` (достижимо) | `exhaustive` | те же | Свидетель, 2 шага: `x = 2`, `x = x + 2`; конечное состояние `x = 4`. Причина от движка: `a reachable state satisfies x == 4; see the witness` |
| R-P4 `reach_x6` | `verified` (достижимо) | `exhaustive` | те же | Свидетель, 2 шага: `x = 2`, `x = x * 3`; конечное состояние `x = 6`. Причина: `a reachable state satisfies x == 6; see the witness` |
| R-P5 `inv_x_le_6` | `verified` | `exhaustive` | те же | Инвариант `x <= 6` выполняется во всех сохранённых состояниях |

Для `reach` слово `verified` читается как «достижимо», а не как «нарушений нет» —
и здесь это хорошая новость: обе ветви `if` живые, значит ни один из двух `assert`
не выполняется вакуумно. Без этой пары санитарных свойств «`assert` не падает»
ничего не стоило бы: недостижимая ветвь тоже никогда не падает.

Обе проверки в переделке проходят по арифметике: `x = 2`, дальше либо `2 + 2 = 4`,
либо `2 * 3 = 6`. Пример из книги и задуман так — он показывает механику встроенного
C, а не ошибку.

## 9. Limitations

1. **Про `simple1.pr` не установлено ничего.** Ни один поиск по этой модели не
   выполнялся. Ни `verified`, ни «скорее всего работает», ни «ошибок нет» —
   ни одного из этих прочтений результат не допускает.
2. **Результаты §7.2 не переносятся на `simple1.pr` сами собой.** `simple1-rewrite.pml`
   — это *другая модель*, и различий два, оба существенные:
   - В оригинале `x` — переменная хоста на C; движок host-код не исполняет и никогда
     не узнает, что на самом деле делает компилятор (переполнение, неопределённое
     поведение, побочные эффекты). В переделке `x = x + 2` — присваивание Promela,
     которое движок исполняет сам. Совпадение результатов держится на моём
     утверждении, что обе строки значат одно и то же, а не на проверке.
   - В переделке `x` входит в вектор состояния (state_bytes 6), а в оригинале — нет
     (допущение A3): без `c_track` SPIN не включает C-переменную в сопоставление
     состояний. Для этой конкретной модели без циклов разница ни на что не влияет,
     но это ровно то различие, ради которого в корпусе рядом лежит `simple2.pr`
     с `c_track`.
3. **Поиск нередуцированный** (в движке нет ни частичных порядков, ни симметрии) —
   на 8 состояниях это несущественно, но записано как факт о прогоне.
4. **Санитарная прогулка (`mc_simulate`) не выполнялась**: в CLI-слое её нет.
   Её роль частично взяли на себя санитарные свойства достижимости R-P3 и R-P4 —
   они, в отличие от прогулки, являются результатами поиска.
5. **Классификация свойств сделана вручную** (`mc_lint_property` доступен только
   через MCP), поэтому строки таблицы §4 — моё суждение, а не вывод инструмента.
6. **Обязательные вопросы рабочего процесса не заданы** — пользователь недоступен;
   вместо них стоят помеченные допущения A1–A6 (§2 и `intake-card.yaml`).
   Для учебного примера это допустимо; для критичной проверки границу системы,
   атомарный шаг и справедливость пришлось бы подтвердить явно.
7. **Аргумента соответствия реализации нет** и не требовался: реализации нет,
   это пример из учебника.
