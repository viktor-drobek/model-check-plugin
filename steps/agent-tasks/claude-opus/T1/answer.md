# Может ли `credits` уйти за границу `byte`?

**Да.** `credits` имеет тип `byte` (0..255), а `issuer` может выполнить `credits++` без
ограничений. Если `spender` ни разу не сходит, то после 256 подряд шагов `credits++`
получится `credits = 256`: значение выходит за пределы `byte` (в SPIN оно молча
обрезалось бы до 0).

Как проверено: встроенный движок model-check (`mc_parse` → `mc_check`, BFS).

- Свойство `deadlock`: статус **`invalid-model`**, причина:
  `domain overflow: credits = 256 leaves [0, 255] (byte domain) in step "credits++"`.
  Кратчайший контрпример состоит из 256 шагов `credits++` процесса `issuer`.
- Проверка достижимости `credits == 255`: `verified` (свидетель: 255 шагов `credits++`).

После переполнения поиск остановился, поэтому другие свойства модели не проверялись.
Выход за нижнюю границу (0 − 1) может случиться только после переполнения: `issuer`
лишь увеличивает счётчик, поэтому между проверкой `credits > 0` и `credits--` значение
станет 0 только через обрезку при переполнении.

Как исправить (это гипотеза, её нужно проверить): ограничить выдачу условием
`:: credits < 255 -> credits++`.

Файлы: модель `credits.pml`, отчёт `mcd-sessions/s20260929-132039-0001/check-1.json`,
контрпример `mcd-sessions/s20260929-132039-0001/cex/cex-1.json`.
