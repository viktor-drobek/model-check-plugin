# Может ли счётчик стать больше 3

**Нет, свойство не выполняется.** `total` доходит до **4**: `violated`, evidence `exhaustive`.

## Почему
Защита `total > 3` в `unless` проверяется **до** инкремента, а не после него.
При `total == 3` защита ложна, инкремент выполняется, и `total` становится 4.
Только на следующем витке срабатывает `break`.

Контрпример (BFS, кратчайший, 8 шагов): 0 → 1 → 2 → 3 → **4**.

## Как проверяли
- Исходная модель (`original.pml`) **не прогонялась** (`not-executed`): встроенный движок не поддерживает `unless` (парсер отклонил строку 7).
- Поэтому модель переписана без `unless` (`rewritten.pml`) — **это изменение модели**:
  `do :: total <= 3 -> total = total + 1 :: else -> break od`.
  По семантике SPIN это эквивалентно: защита выхода проверяется перед каждым шагом основной
  последовательности и имеет приоритет, а тело состоит из одного оператора.
  Эта эквивалентность обоснована вручную; движок её не проверял.
- Результаты по переписанной модели (полный перебор, 11 состояний):
  | Свойство | Статус | Evidence |
  |---|---|---|
  | инвариант `total <= 3` | `violated` | `exhaustive` |
  | проверка адекватности: достижимо `total == 4` | `verified` | `exhaustive` |
  | `deadlock` (некорректное конечное состояние) | `verified` | `exhaustive` |
- Отчёт движка: `mcd-sessions/s20260929-132148-0002/check-1.json`.

## Исправление (гипотеза, не проверялась)
Чтобы максимум был 3, используйте `unless { total >= 3 -> break }`
(или защиту `total < 3` в переписанной форме).
