# Могут ли a, b, c, d одновременно быть равны 200?

**Да, могут.**

Пример: процесс `p1` 200 раз выполняет `a < 255 -> a++`, затем `p2`, `p3` и `p4` делают то же для своих счётчиков.
Получается состояние `a = b = c = d = 200`, на пути 1600 шагов.

## Как проверено

- **Полная модель** (`counters.pml`): у неё примерно (256·3)^4 ≈ 3,5·10^11 состояний, поэтому полный перебор невозможен.
  Поиск `reach` с условием `a==200 && b==200 && c==200 && d==200` исчерпал бюджет в 1 000 000 состояний.
  Итог: `inconclusive` / `bounded`, путь к цели в этом бюджете не найден (`mcd-sessions/…/check-1.json`).
  Сам по себе этот прогон ничего не доказывает и не опровергает.
- **Один счётчик** (`one-counter.pml`, модель ровно `p1`): свойство `EF (a == 200)` получило `verified` / `exhaustive`.
  Граф разобран целиком, 766 состояний (`one-counter-check.json`).
- **Перенос на полную модель:** процессы не делят переменных и не синхронизируются.
  Шаги `p1` меняют только `a`, и их всегда можно выполнить независимо от остальных.
  Поэтому пути четырёх процессов к 200 можно выполнить один за другим.
  Этот перенос я обосновал рассуждением, движок его не выполнял.
- **Проверка на симуляторе:** я проиграл в `mc_simulate` путь, набранный вручную (`sim-2.json`).
  Список шагов оказался короче нужного, поэтому до 200 счётчики не дошли: a=193, b=168, c=169, d=181.
  Прогон показывает только, что счётчики растут независимо. Это не свидетель достижимости состояния 200.

Переполнения `byte` нет: охранные условия `< 255` и `> 0` держат значения в диапазоне 0..255.
