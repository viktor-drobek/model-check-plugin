# Могут ли a, b, c, d одновременно быть равны 200?

**Да, могут, и это верно для модели.** Слепой поиск по полной модели за отведённое время ответа не дал. Ответ получен разложением модели на независимые части.

## Что показал прогон за 1 с

| Прогон | Свойство | Статус | Evidence | Счётчики |
|---|---|---|---|---|
| Полная модель (`counters.pml`), DFS, бюджет 900 мс | `reach a==200 && b==200 && c==200 && d==200` | `inconclusive` | `unknown` (остановка по времени) | 48 128 состояний, глубина 48 126 |
| Один счётчик (`one-counter.pml`), BFS | `reach a == 200` | `verified` | `exhaustive` | 766 состояний, 2 мс, свидетель из 400 шагов |

На полной модели время кончилось раньше, чем поиск что-то нашёл. Это не опровержение и не подтверждение: остановка по времени ничего не говорит о покрытии. Обходить всё пространство бессмысленно: у одного процесса 766 достижимых локальных состояний, у четырёх 766⁴ ≈ 3,4·10¹¹. Такого не обойти ни за секунду, ни в пределах бюджета в 10⁶ состояний.

## Почему ответ «да»

- У процессов нет общих переменных, каналов и общих охран: `p1` читает и пишет только `a`, `p2` только `b` и так далее. Поэтому любое чередование шагов разных процессов можно переставить, и достижимые состояния полной модели — это ровно декартово произведение достижимых состояний отдельных процессов.
- Исчерпывающая проверка одного процесса показала, что `a == 200` достижимо (`verified` / `exhaustive`). Процессы `p2`–`p4` отличаются от `p1` только именем переменной.
- Отсюда свидетель для полной модели: каждый процесс по очереди делает 200 раз `x < 255; x++`. Всего 1600 шагов (800 инкрементов), и в конце a = b = c = d = 200.

Условия: вывод касается модели, а не реальной системы. Слово «независимо» должно означать, что общего состояния действительно нет. Если в реальной системе есть общая блокировка или общий ресурс, разложение неприменимо. Шаг проверки `x < 255` и шаг `x++` не атомарны вместе, но переполнения `byte` это не даёт: переменную меняет только один процесс. Заодно проверено: тупиков в модели одного счётчика нет (`deadlock` `verified` / `exhaustive`).

## Что проверено руками, а не движком

- Утверждение о произведении пространств выведено по коду модели. Движок проверил только модель одного счётчика.
- Свидетель из 1600 шагов на полной модели построен вручную и через `mc_simulate` не прогонялся. Проверен только его первый шаг.

Файлы: `counters.pml`, `one-counter.pml`, отчёты в `mcd-sessions/` (`s20260929-132721-0001/check-1.json` для полной модели, `s20260929-132819-0002/check-1.json` для одного счётчика).
