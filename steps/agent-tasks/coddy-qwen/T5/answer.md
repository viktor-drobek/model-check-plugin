# Ответ

**Зависит от допущения о справедливости (fairness).** Это задача о живости (liveness), а не о безопасности.

Свойство: `[]<> served == 1` — «вторая клиентская задача (`client:1`, `me = 1`) обслуживается бесконечно часто».

| Режим | Результат | Статус / доказательство |
|---|---|---|
| без fairness (чистые интерлевирования) | **НЕТ, не гарантировано** | `violated`, evidence `exhaustive` — найдено бесконечное исполнение |
| weak fairness («непрерывно готовый процесс рано или поздно запускается») | **ДА, гарантировано** | `verified`, evidence `exhaustive`, полный поиск |

## Почему

В модели нет никакого механизма, который *принудительно* исключил бы `client:1`, но семантика параллельности допускает планировщик, который запускает только `client:0`. Модель-контрпример (без fairness) — ласса с циклом: `client:0` бесконечно крутит `want[0]=true; served=0; want[0]=false`, а `client:1` **весь цикл разрешён и никогда не двигается**. На таком пути `served == 1` встречается лишь конечное число раз — свойство нарушено.

При слабой справедливости такой путь исключается, и полный поиск по произведению с автоматом для отрицания (60 состояний) не находит исполнений, удовлетворяющих `!( []<> served == 1 )` — значит, во всех допустимых бесконечных исполнениях второй клиент обслуживается снова и снова.

## Итоговая формулировка

- **Если планировщик может «зависнуть» на одном процессе** → второй клиент может быть обслужен лишь конечное число раз (голодание), гарантированности нет.
- **Если действует слабый fair-расписание** (готовый процесс в конце концов выполняется) → да, второй клиент обслуживается бесконечно часто.

## Методика

- `mcd check --promela model.pml --ltl '[]<> served == 1' --fairness none` → `violated`
- `mcd check --promela model.pml --ltl '[]<> served == 1' --fairness weak` → `verified`
- Рабочие файлы: `model.pml`, `mc-session/none.json`, `mc-session/weak.json`.
