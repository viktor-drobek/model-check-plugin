# Может ли нарушиться взаимное исключение? — Да

**Статус:** `violated`, доказательство `exhaustive` (полный обход: 52 состояния, 96 переходов, BFS, без ограничений справедливости).

## Причина

В Promela охрана и следующий оператор — **два отдельных шага**, между ними возможно
переключение процессов:

```promela
:: !busy ->        /* шаг 1: проверка */
     busy = true;  /* шаг 2: захват — сюда может вклиниться второй клиент */
```

Это классический разрыв «проверил — захватил» (test-and-set не атомарен).
Разбор модели подтверждает это: `!busy` и `busy = true` стали разными рёбрами
автомата (`ir-1.json`, строки 7 и 8).

## Допустимая последовательность (кратчайшая, 7 шагов)

| # | Процесс | Действие | Состояние после |
|---|---------|----------|-----------------|
| 1 | client:0 | `!busy` (охрана проходит, busy == false) | busy=0, inside=0 |
| 2 | client:1 | `!busy` (охрана тоже проходит — busy всё ещё false) | busy=0, inside=0 |
| 3 | client:0 | `busy = true` | busy=1, inside=0 |
| 4 | client:0 | `inside++` | busy=1, **inside=1** |
| 5 | client:1 | `busy = true` (повторно, без эффекта) | busy=1, inside=1 |
| 6 | client:1 | `inside++` | busy=1, **inside=2** |
| 7 | client:0 | `assert(inside == 1)` | **assertion violated** |

Ключ — шаг 2: второй клиент проходит охрану до того, как первый успел выставить
флаг. Оба оказываются в критической секции, `inside == 2`.

## Проверенные свойства

| id | вид | статус | evidence | комментарий |
|----|-----|--------|----------|-------------|
| `mutex` | invariant `inside <= 1` | `violated` | `exhaustive` | контрпример из 6 шагов |
| `assert` | assert модели | `violated` | `exhaustive` | контрпример из 7 шагов (таблица выше) |
| `both_inside` | reach `inside == 2` | `verified` | `exhaustive` | санитарная проверка: состояние достижимо, свидетель найден |
| `deadlock` | deadlock | `verified` | `exhaustive` | тупиков нет |

## Как чинится

Сделать проверку и захват одним неделимым шагом:

```promela
do
:: atomic { !busy -> busy = true };
     inside++;
     assert(inside == 1);
     inside--;
     busy = false
od
```

## Оговорки

- Результат относится к **модели**, не к реальной реализации: перенос требует
  отдельного аргумента (соответствие кода модели).
- Модель конечна и не содержит времени и вероятностей; поиск полный, без редукций
  (partial-order reduction в движке нет).
- Свойств живости (например, «клиент рано или поздно войдёт») не проверялось —
  вопрос был только о взаимном исключении; предположения о справедливости не
  использовались и на результат не влияют.
